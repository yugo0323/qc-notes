# 第 2 回　計算機クラスタでジョブを流す（一般的な考え方）

!!! abstract "この回の道筋"
    量子化学の計算は、多くの利用者が共有する計算機クラスタの上で、「ジョブ」として順番待ちをして実行します。
    この回では、ログインノードと計算ノードの役割、ジョブスケジューラへの頼み方、並列数とメモリーの決め方、スクラッチ領域の使い方、計算の後片付けを学びます。
    施設ごとの細かい決まりは違いますが、ここで扱う考え方はどの施設でも共通です。

    | 節 | 内容 |
    |---|---|
    | 1 | ログインノードと計算ノード |
    | 2 | ジョブスケジューラ |
    | 3 | ジョブスクリプトを書く |
    | 4 | 並列数とメモリーの指定 |
    | 5 | スクラッチ領域 |
    | 6 | 計算の後片付け |

    **前に読んでおく回**：研究の道具 第 1 回 [Linux のコマンドライン](01-linux-command-line.md)

## 1. ログインノードと計算ノード

**計算機クラスタ**（cluster）は、たくさんの計算機をネットワークでつないで、一つの設備として使えるようにしたものです。
一台一台の計算機を**ノード**（node）と呼びます。
ノードは、役割によって 2 種類に分かれます。

- **ログインノード**：利用者が ssh で入るノードです。ファイルの編集、入力の準備、ジョブの投入、結果の確認に使います。
- **計算ノード**：実際の計算をするノードです。利用者は直接ログインせず、次の節のジョブスケジューラを通して使います。

ログインノードは、数台しかないのがふつうで、その数台を全利用者が同時に使っています。
そのため、ログインノードで重い計算を動かすと、ほかの全員の作業が遅くなります。

!!! warning "ログインノードで重い計算をしない"
    量子化学の計算は、どんなに小さくても、ログインノードでは動かさないのが原則です。
    数秒で終わる確認の計算を許す施設もありますが、その範囲は施設の利用の手引きで確かめてください。
    ログインノードで長く動くプログラムを自動で止める施設もあります。

**ここまでで分かったこと**：ログインノードは準備と投入のため、計算ノードは計算のための場所です。

## 2. ジョブスケジューラ

計算ノードの数には限りがあり、利用者の計算をすべて同時には動かせません。
そこで、**ジョブスケジューラ**（job scheduler）というプログラムが、計算の順番と置き場所を決めます。
利用者が頼む一回分の計算を**ジョブ**（job）と呼びます。

流れは次のとおりです。

1. 利用者が、「何コア、どれだけのメモリーを、何時間使い、何を実行するか」を書いた**ジョブスクリプト**を用意します。
2. ジョブスクリプトをスケジューラに渡します（**投入**、submit）。ジョブは**キュー**（queue、待ち行列）に並びます。
3. 頼んだだけの資源が空くと、スケジューラが計算ノードを割り当て、スクリプトを実行します。
4. 計算が終わると、資源が次のジョブに渡されます。

よく使われるスケジューラに、**Slurm** [Yoo 2003] と **PBS** の系統（PBS Pro、OpenPBS、Torque など）があります。
命令の名前は違いますが、できることはほぼ同じです。

| 操作 | Slurm | PBS の系統 |
|---|---|---|
| ジョブを投入する | `sbatch job.sh` | `qsub job.sh` |
| 自分のジョブの状態を見る | `squeue -u $USER` | `qstat -u $USER` |
| ジョブを取り消す | `scancel <ジョブ番号>` | `qdel <ジョブ番号>` |

ジョブを投入すると、スケジューラは**ジョブ番号**を返します。
状態を見たり、取り消したりするときは、この番号を使います。
`$USER` は、自分の利用者名が入った環境変数です（第 1 回の 7 節）。

キューは、施設によって「短い計算用」「大きなメモリー用」「GPU 用」などに分かれています。
どのキューがあり、それぞれ何時間まで、何コアまで使えるかは、施設の利用の手引きに書かれています。

**ここまでで分かったこと**：計算は、ジョブスクリプトをスケジューラに投入して、順番に計算ノードで実行してもらいます。

## 3. ジョブスクリプトを書く

ジョブスクリプトは、bash のスクリプトの先頭に、スケジューラへの頼みごとを特別な注釈として書いたものです。
bash にとっては `#` で始まる行はただの注釈ですが、スケジューラは `#SBATCH` や `#PBS` で始まる行を読みます。

Slurm の例を示します。
1 つのノードで 8 コアと 16 GB のメモリーを 2 時間使い、プログラム `myprog` を実行します。
`myprog` と、キューの名前 `<キューの名前>` は、説明のための仮の名前です。

```bash
#!/bin/bash
#SBATCH --job-name=h2o_opt         # ジョブの名前
#SBATCH --partition=<キューの名前>  # Slurm ではキューを partition と呼ぶ
#SBATCH --nodes=1                  # ノードの数
#SBATCH --ntasks=1                 # プロセスの数
#SBATCH --cpus-per-task=8          # 1 プロセスあたりのコアの数
#SBATCH --mem=16G                  # 1 ノードあたりのメモリー
#SBATCH --time=02:00:00            # 時間の上限（時:分:秒）
#SBATCH --output=%x_%j.log         # 画面への出力を書くファイル（%x はジョブ名、%j はジョブ番号）

export OMP_NUM_THREADS=$SLURM_CPUS_PER_TASK
myprog h2o.inp > h2o.out
```

同じ内容を PBS Pro の書き方で書くと、次のようになります。

```bash
#!/bin/bash
#PBS -N h2o_opt
#PBS -q <キューの名前>
#PBS -l select=1:ncpus=8:mem=16gb
#PBS -l walltime=02:00:00
#PBS -j oe

cd "$PBS_O_WORKDIR"
export OMP_NUM_THREADS=8
myprog h2o.inp > h2o.out
```

`#PBS` の各行は、上から順に、ジョブの名前、キュー、資源（8 コアと 16 GB のメモリーを 1 組）、時間の上限、標準出力と標準エラー出力を 1 つのファイルにまとめる指定です。
`#PBS` の行の後ろに注釈を書けるかどうかは版によって確かでないので、この例では注釈を付けていません。

2 つの例の違いで、つまずきやすいのは実行の始まる場所です。
Slurm は、ジョブを投入したディレクトリでスクリプトを実行し始めます。
PBS の系統は、ふつうホームディレクトリで実行し始めるので、投入したディレクトリ（`$PBS_O_WORKDIR` に入っています）へ `cd` で移る必要があります。
この行を忘れると、プログラムが入力ファイルを見つけられません。

資源の書き方は、同じ PBS の系統でも版によって違います（たとえば Torque では `-l nodes=1:ppn=8` と書きます）。
施設の利用の手引きにある例を元にして書くのが確実です。

時間の上限を過ぎると、ジョブは途中で止められます。
上限を長くしすぎると、空きを待つ時間が長くなりがちです。
初めての種類の計算は、まず小さな分子や短い時間で試し、かかる時間を見積もってから本番を投入します。

計算ノードの上で命令を打ちながら試したいときは、**対話型のジョブ**を使います。
Slurm では `srun --pty bash`、PBS の系統では `qsub -I` が、その命令です（施設によって必要なオプションが違います）。

**ここまでで分かったこと**：ジョブスクリプトには、資源の量と実行する命令を書きます。スケジューラによって書き方と実行の始まる場所が違います。

## 4. 並列数とメモリーの指定

量子化学のプログラムは、複数のコアを使って計算を速くします。
並列の仕方には、大きく 2 種類あります。

- **プロセス並列**（MPI など）：別々のプロセスが、それぞれ自分のメモリーを持って計算し、通信で結果をやり取りします。複数のノードにまたがって使えます。MPI（Message Passing Interface）は、そのための通信の決まりです [Gropp 2014]。
- **スレッド並列**（OpenMP など）：1 つのプロセスの中の複数のスレッドが、同じメモリーを共有して計算します。1 つのノードの中だけで使えます。

どちらを使うかはプログラムによって決まっているので、プログラムの説明書で確かめます。
Slurm の例では、MPI のプロセスの数を `--ntasks`、1 プロセスあたりのスレッドの数を `--cpus-per-task` で頼みます。

大事なのは、**頼んだ数と、プログラムに使わせる数をそろえる**ことです。
プログラムの入力で指定する並列数と、環境変数 `OMP_NUM_THREADS` が、スケジューラに頼んだコアの数を超えないようにします。
超えると、1 つのコアを複数のスレッドが取り合うので、かえって遅くなることがあります。
同じノードにほかの人のジョブがあれば、その人の計算も遅くします。
反対に、頼んだ数より少なく使うと、空いたコアが無駄になります。

メモリーにも同じことが言えます。
量子化学のプログラムの多くは、入力で使うメモリーの量を指定します。
指定の意味はプログラムによって違い、たとえば ORCA の `%maxcore` は 1 プロセスあたりの量、Gaussian の `%mem` はジョブ全体の量です。
プログラムに指定する量の合計は、スケジューラに頼んだ量より少なめにしておきます。
プログラムは、指定した量のほかにも少しメモリーを使うからです。
頼んだ量を超えると、スケジューラがジョブを止めることがあります。

**ここまでで分かったこと**：並列数とメモリーは、スケジューラに頼んだ量と、プログラムに使わせる量をそろえます。

## 5. スクラッチ領域

量子化学の計算は、途中で大きな一時ファイル（2 電子積分や、途中の波動関数など）を作ることがあります。
多くの施設では、ホームディレクトリはネットワーク越しに共有されています。
そこに大きな一時ファイルを書くと、読み書きが遅く、ほかの利用者の読み書きも遅くします。
そこで、一時ファイルは**スクラッチ領域**（scratch）に書きます。

スクラッチ領域は、一時ファイルのために用意された、速い読み書きのできる場所です。
計算ノードの中のディスクであることも、施設全体で共有する速いファイルシステムであることもあります。
多くの施設では、スクラッチ領域のファイルは一定の期間で消されるか、ジョブが終わると消されます。
置き場所の名前（`/scratch`、`/work`、環境変数 `$TMPDIR` など）は施設によって違います。

使い方の基本は、「入力をスクラッチに写す → そこで計算する → 必要な結果だけを持ち帰る → スクラッチを消す」です。
Slurm のスクリプトで書くと、次のようになります。
`/scratch/$USER` は仮の場所で、実際には施設の決めた場所に合わせます。

```bash
#!/bin/bash
#SBATCH --nodes=1
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=8
#SBATCH --mem=16G
#SBATCH --time=02:00:00

WORK="$SLURM_SUBMIT_DIR"                 # 投入したディレクトリ
SCR="/scratch/$USER/$SLURM_JOB_ID"       # ジョブごとに別のスクラッチ
mkdir -p "$SCR"

cp "$WORK/h2o.inp" "$SCR/"
cd "$SCR"
export OMP_NUM_THREADS=$SLURM_CPUS_PER_TASK
myprog h2o.inp > h2o.out

cp h2o.out "$WORK/"                       # 必要な結果だけを持ち帰る
cd "$WORK"
rm -rf "$SCR"                             # スクラッチを片付ける
```

ジョブ番号 `$SLURM_JOB_ID` をディレクトリの名前に入れたのは、同時に動く自分の別のジョブと、一時ファイルが混ざらないようにするためです。
最後の `rm -rf` は、確かめなしに中身ごと消す命令です。
消す対象を変数で書くときは、変数が正しく入っていることを確かめてから使います（第 1 回の 3 節）。

**ここまでで分かったこと**：一時ファイルはスクラッチ領域に書き、必要な結果だけを持ち帰ってから、スクラッチを消します。

## 6. 計算の後片付け

ジョブが終わったら、まず計算が正しく終わったかを確かめます。
プログラムの多くは、正常に終わったときに決まった文を出力の最後に書くので、`tail` や `grep` で確かめられます（第 1 回の 4 節）。
スケジューラの出力ファイル（上の例の `%x_%j.log`）にも、時間切れやメモリー不足で止められた知らせが書かれます。

次に、ファイルを整理します。

- **残すもの**：入力ファイル、ジョブスクリプト、主な出力ファイル、最適化した構造。これがあれば、同じ計算をやり直せます。
- **消すもの**：やり直せば作れる大きな一時ファイル（積分のファイルなど）。スクラッチに残ったものも消します。
- **縮めるもの**：しばらく見ないが残したい大きな出力は、`gzip` などで圧縮します。

ディレクトリの使っている容量は、`du -sh <ディレクトリ>` で表示できます。
多くの施設では、利用者ごとに使える容量（**クォータ**、quota）が決まっていて、超えると新しいファイルを書けなくなり、動いているジョブが失敗することもあります。

計算の記録は、あとで論文を書くときに必要になります。
計算ごとにディレクトリを分け、何の計算かが名前から分かるようにしておくと、後片付けも楽になります。
ファイルの整理の仕方は、研究のデータ管理の勧め [Wilson 2017] も参考になります。
たとえば、元のデータは作られたままの形で残すこと、大事なデータは複数の場所に保管することが勧められています。

**ここまでで分かったこと**：ジョブの後は、正常に終わったかを確かめ、やり直しに必要なものを残して、一時ファイルを消します。

## まとめ

- ログインノードは準備と投入の場所で、重い計算は動かしません。
- 計算は、資源の量と命令を書いたジョブスクリプトを、Slurm や PBS などのスケジューラに投入して実行します。
- 並列数とメモリーは、スケジューラに頼んだ量と、プログラムに使わせる量をそろえます。
- 一時ファイルはスクラッチ領域に書き、終わったら必要な結果だけを持ち帰って消します。
- ジョブの後は、正常終了を確かめ、やり直しに必要なファイルを残して整理します。
