# 第 1 回　Linux のコマンドライン

## 1. シェルとは

**シェル**（shell）は、人が打った命令を読み、計算機に実行させるプログラムです。
命令を打つ画面を**端末**（terminal）と呼びます。
Linux で最もよく使われるシェルは **bash** で、この回の例もすべて bash で書きます。

端末を開くと、次のような行が出て、入力を待ちます。

```console
user@server:~$
```

この行を**プロンプト**（prompt）と呼びます。
`user` は利用者の名前、`server` は計算機の名前、`~` は今いる場所（次の節で説明します）です。
この回では、プロンプトを `$` だけに縮めて書きます。
`$` の後ろが打つ命令で、`$` のない行は命令の出力です。

命令は「命令の名前　オプション　対象」の順に、空白で区切って書きます。

```console
$ ls -l project
```

`ls` が命令の名前、`-l` がオプション（命令の動き方を変える指定）、`project` が対象です。
命令の詳しい使い方は、`man ls` で説明書（マニュアル）を開くか、`ls --help` で短い説明を出して調べます。

命令を体系的に学びたい人には、教科書 [Shotts 2019] が向いています。

**ここまでで分かったこと**：シェルは打った命令を実行するプログラムで、命令は「名前・オプション・対象」の順に書きます。

## 2. ディレクトリとパス

Linux のファイルは、**ディレクトリ**（directory、Windows のフォルダと同じもの）の中に入っています。
ディレクトリの中にさらにディレクトリを置けるので、全体は 1 本の木の形になります。
木の根元を**ルート**（root）と呼び、`/` で表します。

ファイルの場所は、ディレクトリの名前を `/` でつないだ**パス**（path）で表します。
たとえば `/home/user/project/h2o.inp` は、ルートの下の `home` の下の `user` の下の `project` にある `h2o.inp` です。

利用者ごとに、自分のファイルを置く**ホームディレクトリ**があります。
上の例では `/home/user` がホームディレクトリで、シェルでは `~` と短く書けます。
つまり `~/project` は `/home/user/project` と同じ場所です。

パスには 2 種類あります。

- **絶対パス**：`/` から書き始めるパス。どこにいても同じ場所を指します。
- **相対パス**：今いるディレクトリから見たパス。`.` は今いるディレクトリ、`..` は一つ上のディレクトリを表します。

今いるディレクトリは `pwd` で表示し、`cd` で移ります。

```console
$ pwd
/home/user
$ cd project
$ pwd
/home/user/project
$ cd ..
$ pwd
/home/user
```

`cd` だけを打つと、ホームディレクトリに戻ります。
ディレクトリの中身は `ls` で一覧にします。
`ls -l` は大きさや更新日時も表示し、`ls -a` は名前が `.` で始まる隠しファイルも表示します。

**ここまでで分かったこと**：ファイルの場所はパスで表し、`pwd`・`cd`・`ls` で今の場所を確かめながら動きます。

## 3. ファイルを作る・写す・動かす・消す

計算を始めるときは、まず計算ごとにディレクトリを作ります。
`mkdir` がディレクトリを作る命令で、`-p` を付けると途中のディレクトリもまとめて作ります。

```console
$ mkdir -p ~/project/h2o/opt
```

ファイルの複製は `cp`、移動と名前の変更は `mv` で行います。

```console
$ cp h2o.inp h2o_b3lyp.inp       # h2o.inp を h2o_b3lyp.inp という名前で複製する
$ mv h2o_b3lyp.inp opt/          # opt ディレクトリの中へ移す
$ mv opt/h2o_b3lyp.inp opt/h2o.inp   # 名前を変える
$ cp -r opt opt_backup           # ディレクトリを中身ごと複製する（-r）
```

`#` から行の終わりまでは、シェルが読み飛ばす注釈（コメント）です。

ファイルを消す命令は `rm` です。
ディレクトリを中身ごと消すには `rm -r` を使います。

!!! warning "rm は取り消せません"
    `rm` で消したファイルは、Windows や macOS の「ごみ箱」に入らず、その場で消えます。
    元に戻す命令はありません。
    また、`*` は「どんな文字の並びにも合う」という意味の記号なので、`rm *.out` は今のディレクトリの `.out` で終わるファイルをすべて消します。
    `rm * .out` のように空白が一つ入るだけで、今のディレクトリのファイルがすべて消えます。
    慣れるまでは、`rm -i`（1 件ずつ確かめる）を使い、消す前に `ls *.out` で対象を表示して確かめてください。
    大事な結果は、別の場所に写しを置いておきます。

**ここまでで分かったこと**：`mkdir`・`cp`・`mv`・`rm` でファイルを整理します。`rm` は取り消せないので、消す前に対象を確かめます。

## 4. ファイルの中身を読む・探す

計算の出力ファイルは長いので、全体を一度に表示せず、必要な部分だけを見ます。
ここでは、次のような小さなファイル `scan.log` を例にします。
H₂ の結合距離 R を変えながらエネルギー E を計算した記録を、説明のために自分で作ったものです。

```text
step 1  R = 0.60  E = -1.0560
step 2  R = 0.70  E = -1.1175
step 3  R = 0.80  E = -1.1341
step 4  R = 0.90  E = -1.1285
step 5  R = 1.00  E = -1.1102
warning: slow convergence at step 5
step 6  R = 1.10  E = -1.0884
```

`less` は、ファイルを 1 画面ずつ読む命令です。
矢印キーやスペースキーで進み、`/` の後に言葉を打つとその言葉を探し、`q` で終わります。
ファイルの先頭と末尾だけを見るときは、`head` と `tail` を使います。

```console
$ head -n 3 scan.log
step 1  R = 0.60  E = -1.0560
step 2  R = 0.70  E = -1.1175
step 3  R = 0.80  E = -1.1341
$ tail -n 2 scan.log
warning: slow convergence at step 5
step 6  R = 1.10  E = -1.0884
```

`tail -f` は、ファイルに行が書き足されるたびに表示し続けます。
計算の途中経過を見るのに便利で、`Ctrl` キーと `C` キーを同時に押すと止まります。

ファイルの中から、ある言葉を含む行だけを取り出すのが `grep` です。
`-n` を付けると行の番号も表示し、`-i` を付けると大文字と小文字を区別しません。

```console
$ grep -n -i warning scan.log
6:warning: slow convergence at step 5
```

実際の計算でも、「エネルギーの値が書かれた行に必ず出る言葉」や「エラーの行に出る言葉」で `grep` すれば、長い出力から必要な行をすぐに見つけられます。

**ここまでで分かったこと**：長いファイルは `less`・`head`・`tail` で部分的に読み、`grep` で必要な行を取り出します。

## 5. パイプとリダイレクト

ここまでの命令は、結果を画面に表示しました。
この表示先を変える仕組みが、パイプとリダイレクトです。

**パイプ**（pipe）`|` は、左の命令の出力を、右の命令の入力に渡します。
たとえば、エネルギーの行の数を数えるには、`grep` の出力を、行を数える命令 `wc -l` に渡します。

```console
$ grep "E =" scan.log | wc -l
6
```

パイプは何段でもつなげます。
次の例は、エネルギーの行を 8 番目の欄（空白で区切った 8 つ目の項目、つまりエネルギーの値）の数の小さい順に並べ（`sort -k 8 -n`）、先頭の 1 行だけを表示します。
つまり、エネルギーが最も低い点を探しています。

```console
$ grep "E =" scan.log | sort -k 8 -n | head -n 1
step 3  R = 0.80  E = -1.1341
```

**リダイレクト**（redirect）`>` は、出力を画面ではなくファイルに書きます。
次の例では、`awk '{print $5, $8}'`（各行の 5 番目と 8 番目の欄を表示する命令）で R と E だけを取り出し、`curve.dat` に保存しています。

```console
$ grep "E =" scan.log | awk '{print $5, $8}' > curve.dat
$ cat curve.dat
0.60 -1.0560
0.70 -1.1175
0.80 -1.1341
0.90 -1.1285
1.00 -1.1102
1.10 -1.0884
```

`cat` は、ファイルの中身をそのまま表示する命令です。
こうして作った 2 列のファイルは、第 4 回で扱うグラフの材料になります。

計算が 100 個に増えても、この 1 行の命令はそのまま使えます。
同じ作業を手で繰り返さずに計算機にやらせ、使った命令をファイルに残して再利用することは、研究でプログラムを使うときの基本的な心がけとして勧められています [Wilson 2014]。
打った命令の記録は `history` で表示でき、上矢印キーで前の命令を呼び出せます。

`>` は、同じ名前のファイルがあると、中身を上書きします。
ファイルの末尾に書き足すときは `>>` を使います。
また、プログラムはエラーの知らせを、ふつうの出力とは別の出口（**標準エラー出力**）に出します。
これをファイルに書くには `2>` を使います。

```console
$ ./run_calc > calc.out 2> calc.err
```

**ここまでで分かったこと**：`|` で命令をつなぎ、`>`・`>>`・`2>` で出力をファイルに書きます。これで、出力から数値の表を作れます。

## 6. 権限

Linux の各ファイルには、「誰が何をしてよいか」という**権限**（permission）が決められています。
`ls -l` の行の先頭に、それが表示されます。

```console
$ ls -l curve.dat
-rw-r--r-- 1 user users 78 Nov 17 01:11 curve.dat
```

先頭の 1 文字は種類（`-` はふつうのファイル、`d` はディレクトリ）です。
残りの 9 文字は、3 文字ずつ「持ち主」「グループ（同じ組に属する利用者）」「その他の全員」の権限を表します。
`r` は読める、`w` は書ける、`x` は実行できる、`-` はできない、という意味です。
上の例では、持ち主だけが書き込めて、ほかの人は読むだけです。

権限は `chmod` で変えます。

```console
$ chmod u+x run.sh      # 持ち主（u）に実行（x）の権限を足す
$ chmod go-r secret.txt # グループ（g）とその他（o）から読む権限（r）を外す
$ chmod 600 key.txt     # 持ち主だけが読み書きでき、ほかは何もできない
```

最後の例の `600` は、3 つの組の権限を数字で書いたものです。
各組で、読むを 4、書くを 2、実行を 1 として足します（`6 = 4 + 2`）。
自分で書いたシェルスクリプトを `./run.sh` のように実行するには、`x` の権限が要ります。
共用の計算機では、他人に見せたくないファイルの `r` を外しておきます。

**ここまでで分かったこと**：権限は持ち主・グループ・その他ごとに r・w・x で決まり、`chmod` で変えます。

## 7. 環境変数と PATH

シェルは、設定を**環境変数**（environment variable）という名前付きの値として持っています。
変数の値は、名前の前に `$` を付けて取り出します。

```console
$ echo $HOME
/home/user
```

`echo` は、後ろに書いたものを表示する命令です。
自分で変数を作り、そのシェルから起動するプログラムにも渡すには `export` を使います。

```console
$ export OMP_NUM_THREADS=4
```

`OMP_NUM_THREADS` は、OpenMP（1 台の計算機の中で処理を並列にする仕組み）を使うプログラムに、使うスレッドの数を伝える変数です。
量子化学のプログラムの多くは、このような環境変数で動き方を指定します。

特に大事な環境変数が **PATH** です。
`ls` と打つだけで動くのは、シェルが PATH に並んだディレクトリの中から `ls` という名前のプログラムを探して実行するからです。

```console
$ echo $PATH
/usr/local/bin:/usr/bin:/bin
$ which ls
/usr/bin/ls
```

PATH は、ディレクトリを `:` で区切って並べたもので、前にあるものから順に探します。
`which` は、実際にどのプログラムが使われるかを表示します。
自分でインストールしたプログラムを名前だけで動かすには、そのディレクトリを PATH に足します。

```console
$ export PATH=$HOME/opt/myprog/bin:$PATH
```

この設定は、その端末を閉じると消えます。
毎回使う設定は、bash が起動するときに読む設定ファイル `~/.bashrc` に書いておきます。
（ログインのときには `~/.bash_profile` が読まれますが、多くの計算機では、その中から `~/.bashrc` を読むように設定されています。）
同じ名前のプログラムが 2 か所にあると、PATH で前にある方が使われます。
思ったのと違う版のプログラムが動いたときは、まず `which` で確かめます。

**ここまでで分かったこと**：環境変数でシェルとプログラムの動きを決めます。PATH は、命令の名前からプログラムを探す場所の一覧です。

## 8. ssh：ほかの計算機に入る

研究で使う大きな計算機（第 2 回で扱う計算機クラスタ）には、手元のパソコンからネットワーク越しにログインします。
そのための命令が **ssh**（secure shell）です。
ssh は通信を暗号化するので、途中で盗み見されても中身は読めません。

```console
$ ssh user@cluster.example.org
```

`user` は向こうの計算機での利用者名、`cluster.example.org` は計算機の名前です。
ログインすると、プロンプトが向こうの計算機のものに変わり、ここまでの命令がそのまま使えます。
`exit` で手元に戻ります。

ログインの確かめ方には、パスワードのほかに**鍵**（key）を使う方法があり、多くの施設は鍵の方式を求めます。
鍵は、**秘密鍵**と**公開鍵**の 2 つのファイルの組です。
公開鍵を向こうの計算機に登録しておくと、対になる秘密鍵を持つ人だけがログインできます。
鍵の組は手元で作ります。

```console
$ ssh-keygen -t ed25519
```

`-t ed25519` は、鍵の作り方（暗号の方式）の指定です。
標準では `~/.ssh/id_ed25519`（秘密鍵）と `~/.ssh/id_ed25519.pub`（公開鍵）ができます。
施設に渡すのは、名前が `.pub` で終わる公開鍵だけです。

!!! warning "秘密鍵は誰にも渡さない"
    秘密鍵を持つ人は、あなたとしてログインできます。
    秘密鍵をメールで送ったり、共有のフォルダや第 5 回で扱う GitHub に置いたりしてはいけません。
    秘密鍵の権限は `chmod 600` にしておきます（権限が広いと、ssh は秘密鍵を使うのを断ります）。

手元と計算機の間でファイルをやり取りするには、ssh の仕組みを使う `scp` や `rsync` を使います。

```console
$ scp h2o.inp user@cluster.example.org:~/project/       # 手元から計算機へ
$ scp user@cluster.example.org:~/project/h2o.out .      # 計算機から手元の今の場所（.）へ
$ rsync -av project/ user@cluster.example.org:~/project/ # ディレクトリをまとめて同期する
```

`rsync` は、すでに同じ中身のファイルを送らないので、大きなディレクトリを何度も写すときに向いています。

**ここまでで分かったこと**：ssh で暗号化された通信を使ってほかの計算機に入り、鍵でログインします。秘密鍵は手元から出しません。

## まとめ

- シェルは打った命令を実行するプログラムで、ファイルの場所は絶対パスか相対パスで表します。
- `ls`・`cd`・`pwd`・`mkdir`・`cp`・`mv`・`rm` でファイルを整理します。`rm` は取り消せません。
- `less`・`head`・`tail`・`grep` で出力ファイルを読み、`|` と `>` で必要な数値の表を作ります。
- 権限は `chmod` で、プログラムを探す場所は環境変数 PATH で決めます。
- ssh と鍵でほかの計算機に入ります。秘密鍵は誰にも渡しません。
