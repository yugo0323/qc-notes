## 1. 入力ファイルの全体の形

Gaussian は、商用の量子化学計算プログラムです。
入力は、テキストファイル（拡張子は `.gjf` や `.com` がよく使われます）に書きます。
まず、水分子を HF/STO-3G で構造最適化し、続けて振動解析をする入力の全体を示します。

```text
%nprocshared=1
%mem=500MB
%chk=h2o_opt.chk
# HF/STO-3G Opt Freq

H2O optimization and frequencies

0 1
O    0.000000    0.000000    0.117300
H    0.000000    0.757200   -0.469200
H    0.000000   -0.757200   -0.469200

```

入力は、上から次の部分でできています。

| 部分 | この例での行 | 役割 |
|---|---|---|
| Link 0 の行 | `%` で始まる 3 行 | メモリー、並列数、ファイル名などの実行の設定 |
| ルートセクション | `#` で始まる行 | 計算方法、基底関数、計算の種類 |
| 空行 | | ルートセクションの終わり |
| タイトル | `H2O optimization ...` | 計算の説明（計算の中身には影響しない） |
| 空行 | | タイトルの終わり |
| 電荷と多重度 | `0 1` | 分子全体の電荷とスピン多重度 |
| 座標 | 元素記号と $x, y, z$ の行 | 原子の位置（Å） |
| 空行 | | 分子の指定の終わり |

空行は、区切りの記号として意味をもちます。
特に、最後の座標の行の後ろの空行を忘れると、Gaussian は入力の終わりを正しく読めずに止まります。
逆に、ルートセクションとタイトルの間に余計な空行を入れても、区切りがずれて読めなくなります。

Linux の計算機では、次のように実行します。

```bash
g16 < h2o_opt.gjf > h2o_opt.log
```

`<` で入力ファイルを渡し、`>` で出力をファイルに書きます。
計算の途中の一時ファイルを置く場所は、環境変数 `GAUSS_SCRDIR` で指定します。
計算機クラスターでは、ジョブスクリプトの中でこの命令を実行します。

**ここまでで分かったこと**：入力は「Link 0 → ルート → タイトル → 電荷と多重度 → 座標」の順に書き、空行で区切ります。

## 2. Link 0 の行（% 行）

`%` で始まる行は、計算の中身ではなく、実行のしかたを指定します。
よく使うのは次の四つです。

| 行 | 意味 |
|---|---|
| `%mem=4GB` | 計算に使ってよいメモリーの量（ジョブ全体） |
| `%nprocshared=8` | 使う CPU のコアの数（共有メモリー並列） |
| `%chk=name.chk` | チェックポイントファイルの名前 |
| `%oldchk=old.chk` | 前の計算のチェックポイントファイルを読み込む |

`%mem` は、単位をつけずに書くと 8 バイトの「語」を単位とした数と解釈されます。
間違いを避けるため、`MB` や `GB` をつけて書きます。
公式の文書によると、指定しない場合の既定値は 800 MB です。
第 3 回で見たとおり、`%mem` はジョブ全体の量なので、計算機やジョブに割り当てられた量より少なめにします。

チェックポイントファイルには、最後の構造、分子軌道、力の定数などが保存されます。
あとの計算で読み込んだり、可視化ソフトで軌道を描いたりするのに使います（6 節）。

**ここまでで分かったこと**：`%mem`（全体のメモリー）、`%nprocshared`（コア数）、`%chk`（チェックポイントファイル）で実行のしかたを指定します。

## 3. ルートセクション（# 行）

`#` で始まる行が、ルートセクションです。
ここに、計算方法、基底関数、計算の種類を、空白で区切って並べます。

```text
# HF/STO-3G Opt Freq
```

この行の意味は、「HF/STO-3G のレベルで、構造最適化（Opt）をし、続けて振動解析（Freq）をする」です。
`Opt` と `Freq` を同じ行に書くと、Gaussian は最適化が終わった構造で、自動的に振動解析を行います。
第 1 回で見た「振動解析は最適化と同じ計算レベルで」という条件も、こうすれば自然に満たされます。

ルートセクションは、1 行に収まらなければ複数の行に分けて書けます。
終わりには空行を置きます。

`#` の後ろに 1 文字を加えると、出力の詳しさを変えられます。
`#N`（または `#` だけ）はふつうの量、`#P` は SCF の収束の様子などを加えた詳しい出力、`#T` は要点だけの短い出力です。
計算がうまくいかない原因を調べるときは、`#P` が便利です。

キーワードに選択肢をつけるときは、`Opt=TS` のように `=` で書きます。
選択肢が複数あるときは、`Opt=(TS,CalcFC)` のように括弧の中にカンマで区切って書きます。

**ここまでで分かったこと**：ルートセクションに「方法/基底関数」と計算の種類を書きます。選択肢は `キーワード=(選択肢, …)` の形で書きます。

## 4. タイトル、電荷と多重度、座標

**タイトル**は、計算の内容のメモです。
出力の中に書き写されるだけで、計算には影響しません。
公式の文書によると、タイトルは 5 行までです。`@`、`#`、`!`、`-`、`_`、`\` などの記号は避けるよう求められています。

**電荷と多重度**の行には、二つの整数を、電荷、多重度の順に書きます。
`0 1` は「中性の一重項」、`0 2` は「中性の二重項」、`-1 1` は「1 価の陰イオンの一重項」です。
決め方は第 3 回で学びました。
多重度が 1 より大きく、方法に R、U、RO をつけない場合、Gaussian は非制限（UHF や UKS）で計算します。

**座標**は、xyz 形式の 3 行目以降と同じく、元素記号と $x, y, z$（Å）を 1 行に 1 原子ずつ書きます。
第 2 回の Z 行列で書くこともできます。
xyz ファイルの 1 行目（原子数）と 2 行目（注釈）は、貼り付けないように注意します。

**ここまでで分かったこと**：タイトルは計算に影響しないメモです。電荷と多重度は「電荷 多重度」の順に書き、座標は元素記号と直交座標で書きます。

## 5. よく使うキーワード

ルートセクションでよく使うキーワードを、役割ごとにまとめます。

### 5.1 計算の種類

| キーワード | 意味 |
|---|---|
| `SP` | 一点計算（与えた構造でエネルギーだけを計算する）。計算の種類を書かなければ、これになる |
| `Opt` | 構造最適化（極小を探す） |
| `Opt=TS` | 遷移状態（1 次の鞍点）を探す |
| `Opt=CalcFC` | 最適化の最初に、力の定数（ヘシアン）を計算してから始める |
| `Opt=(MaxCycles=N)` | 最適化の繰り返しの上限を N 回にする |
| `Freq` | 振動解析と熱化学の計算（第 5 回） |

遷移状態の探索は、出発の構造の近くのエネルギーの曲がり方の情報が大切です。
そのため、`Opt=(TS,CalcFC)` のように、最初にヘシアンを計算することがよくあります。

### 5.2 計算方法と基底関数

方法と基底関数は「方法/基底関数」の形で書きます（例：`B3LYP/6-31G(d)`、`PBE0/Def2TZVP`）。
def2 系の基底関数は、Gaussian では `Def2SVP`、`Def2TZVP` のように、ハイフンなしで書きます。
DFT の分散補正は、汎関数とは別のキーワード `EmpiricalDispersion` で加えます。
たとえば、Becke–Johnson 減衰つきの D3 補正なら `EmpiricalDispersion=GD3BJ` です。
次の行は、水分子で実際に動かして確かめたものです。

```text
#P B3LYP/Def2SVP EmpiricalDispersion=GD3BJ Opt
```

出力には、分散補正のエネルギーを示す行（`Grimme-D3(BJ) Dispersion energy=`）が出ます。
補正を加えたつもりでも、この行がなければ加わっていません。

DFT の数値積分のグリッドは、公式の文書によると、Gaussian 16 の既定は `UltraFine` です。
ほかの版や、ほかのプログラムの結果と比べるときは、グリッドの違いにも注意します。

### 5.3 SCF の設定

| キーワード | 意味 |
|---|---|
| `SCF=(MaxCycle=N)` | SCF の繰り返しの上限を N 回にする |
| `SCF=XQC` | ふつうの方法で収束しなければ、2 次の収束法に切り替える |
| `SCF=QC` | 初めから 2 次の収束法を使う（制限開殻には使えない） |
| `Guess=Read` | チェックポイントファイルの軌道を、SCF の出発点にする |
| `Stable` | 得られた波動関数の安定性を調べる（第 3 回） |

第 3 回で学んだ SCF の対処法は、これらのキーワードで指定します。
公式の文書によると、Gaussian 16 では `SCF=Tight` の収束条件が既定です。
実際の閾値は、出力の `Requested convergence on RMS density matrix=` の行で確かめられます。

**ここまでで分かったこと**：計算の種類（`Opt`、`Freq` など）、「方法/基底関数」、分散補正、SCF の設定を、ルートセクションのキーワードで指定します。

## 6. 計算をつなぐ：チェックポイントファイルと Link1

一つの入力ファイルに、複数の計算を順に書けます。
二つ目以降の計算の前に `--Link1--` という行を置きます。
次の例は、構造最適化のあと、最適化した構造で振動解析をする入力です。

```text
%nprocshared=1
%mem=1GB
%chk=h2o_dft.chk
#P B3LYP/Def2SVP EmpiricalDispersion=GD3BJ Opt

H2O optimization with B3LYP and GD3BJ

0 1
O    0.000000    0.000000    0.117300
H    0.000000    0.757200   -0.469200
H    0.000000   -0.757200   -0.469200

--Link1--
%nprocshared=1
%mem=1GB
%chk=h2o_dft.chk
#P B3LYP/Def2SVP EmpiricalDispersion=GD3BJ Freq Geom=Check Guess=Read

H2O frequencies at the optimized geometry

0 1

```

二つ目の計算では、座標を書いていません。
`Geom=Check` が、チェックポイントファイルに残った最後の構造（最適化した構造）を読むからです。
`Guess=Read` は、同じファイルの分子軌道を SCF の出発点にします。
電荷と多重度の行は、`Geom=Check` のときも書きます。
`--Link1--` の前には空行が必要です。

この形は、最適化の途中で止まった計算を、最後の構造から再開するときにも使えます。
前の計算のファイルを書き換えたくないときは、`%oldchk` で前のファイルを読み、`%chk` で新しい名前のファイルに書きます。

**ここまでで分かったこと**：`--Link1--` で計算をつなぎ、`Geom=Check` と `Guess=Read` でチェックポイントファイルの構造と軌道を引き継ぎます。

## 7. 構造最適化の出力を読む

1 節の入力を実行すると、出力ファイル `h2o_opt.log` ができます。
この例は、1 コアで 1 秒ほどで終わりました。
出力は長いので、要点の行を検索して読みます。

### 7.1 SCF のエネルギー

最適化の各段階で、SCF が収束するたびに次の形の行が出ます。

```text
 SCF Done:  E(RHF) =  -74.9659011638     A.U. after    6 cycles
```

`E(RHF)` は RHF のエネルギーで、単位はハートリー（`A.U.` は原子単位の意味）です。
`after 6 cycles` は、SCF が 6 回の繰り返しで収束したことを表します。
最適化が進むにつれて、この値は下がっていきます。
この例では、最初の構造の $-74.96302$ から、最後の $-74.96590$ まで下がりました。

### 7.2 収束判定の 4 項目

最適化の各段階の終わりには、収束を判定する表が出ます。
この例の最後の段階の表は、次のとおりです。

```text
         Item               Value     Threshold  Converged?
 Maximum Force            0.000182     0.000450     YES
 RMS     Force            0.000149     0.000300     YES
 Maximum Displacement     0.000223     0.001800     YES
 RMS     Displacement     0.000202     0.001200     YES
```

4 行は、次の量を表します（値は原子単位です）。
`Threshold` の列は、`Opt` の既定の閾値です。

| 項目 | 意味 |
|---|---|
| Maximum Force | 原子に働く力の成分のうち、最も大きいもの |
| RMS Force | 力の成分の 2 乗平均の平方根（全体としての大きさ） |
| Maximum Displacement | 次の段階で動かす予定の量のうち、最も大きいもの |
| RMS Displacement | 動かす量の 2 乗平均の平方根 |

`Value` が `Threshold`（閾値）より小さければ `YES` になります。
力の 2 項目は「いまの構造で勾配がほぼゼロか」を、変位の 2 項目は「これ以上動かしても構造がほとんど変わらないか」を調べています。
第 1 回で見たとおり、勾配がゼロの点が停留点です。

4 項目がすべて `YES` になると、次の行が出て最適化が終わります。

```text
    -- Stationary point found.
```

この例では、4 回目の段階で 4 項目がすべて `YES` になりました。
最初の段階では、Maximum Force が 0.037498 と閾値の 80 倍以上あり、4 項目とも `NO` でした。

### 7.3 最適化した構造と終わり方

最適化した構造は、`Stationary point found` のあとに、結合の長さや角度の表として出ます。
直交座標は、その後ろの `Standard orientation` の表で読めます。
Gaussian は、計算の途中で分子を、決まった基準の向き（標準配向）に移して扱います。
そのため、この座標は入力の座標と位置や向きが違うことがあります。
入力と同じ向きの座標は `Input orientation` の表に出ます。

出力の最後に `Normal termination of Gaussian 16` があれば、計算は正常に終わっています。
`Opt Freq` のように計算を二つつなげた場合は、この行が 2 回出ます。
`Error termination` で終わった場合は、その直前の数行に、止まった理由の手がかりが書かれています。

最適化の繰り返しが上限に達すると、すべてが `YES` になる前に計算が止まります。
そのときは、6 節の方法で最後の構造から再開するか、`Opt=CalcFC` で最初のヘシアンを良くしてやり直します。

**ここまでで分かったこと**：最適化の収束は、力と変位の 4 項目がすべて閾値より小さくなったかで判定し、`Stationary point found` で確かめます。計算全体の終わり方は `Normal termination` で確かめます。

## まとめ

- Gaussian の入力は「Link 0 の % 行 → ルートセクションの # 行 → タイトル → 電荷と多重度 → 座標」の順に書き、空行で区切ります。
- `%mem` はジョブ全体のメモリー、`%nprocshared` はコア数、`%chk` はチェックポイントファイルを指定します。
- ルートセクションには「方法/基底関数」と `Opt`、`Freq` などの計算の種類を書き、分散補正は `EmpiricalDispersion` で別に加えます。
- `--Link1--` と `Geom=Check`、`Guess=Read` で、前の計算の構造と軌道を引き継げます。
- 最適化の収束は、Maximum Force、RMS Force、Maximum Displacement、RMS Displacement の 4 項目と、`Stationary point found` で確かめます。
